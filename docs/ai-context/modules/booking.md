- `ReservationRescheduleService` authorizes assigned doctors/admins, locks and validates a replacement slot ULID for the same offering, excludes the current reservation from conflicts, preserves original price/currency/payment facts, appends previous/new slot and time history, and writes fail-closed audit in one transaction.

## Guardrails

- Do not duplicate booking rules between web and API. Move shared rules into a service when changing behavior.
- Do not bypass `BookingService` for reservation/payment creation.
- Keep the selected slot's public-ID locking path consistent across booking, rescheduling, and concurrency tests; mixing secondary/public-ID and primary-ID lock acquisition can deadlock on MySQL.
- Do not treat specialty/category matching as a booking eligibility rule; use the workplace-service pivot.
- Do not change payment lifecycle from booking code unless the payment task is in scope.
- Do not let retrying or creating a payment attempt extend `hold_expires_at`.
- Keep both scheduled cleanup and synchronous validity checks; scheduled work is not an authorization/state-transition guarantee.
- Do not compare enum-cast reservation statuses as raw strings without checking casts.
- Preserve persistent server-owned visit-slot identity. Never accept patient-owned timestamps, owner IDs, slot ends/durations/prices/currencies as booking policy.
