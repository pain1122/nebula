## Questionnaire management

- Admin/root `/panel/questionnaires`, numeric detail/editor, and `/panel/questionnaire-submissions` with an explicit public-ID submission detail lookup. Definition create uses numeric route sentinel `0`; no extra route is introduced.
- Definition title/slug/status/version/author/date filters, draft/published presets, nested questions/scored choices/recommendation ranges, HTML-source editing, ordinary sanitized create/update/publication and soft archival. Panel update/archive sends the expected version; the server compares it under lock. Legacy callers may omit the new version field for compatibility.
- Submission owner/questionnaire/version/date/score filters, result/name/phone/public-ID search and stable pagination; saved answers/result/version are independent of later definition changes or archival. Registered ownership is labelled **account**, not inferred patient role, because the existing public API also accepts other authenticated submitters. Exact saved `user_id` enables patient-account filtering. Guest remains explicit.
- Dedicated admin resources exclude token hashes, raw meta and internal answer IDs. Lists omit answers/result body; expired detail returns an explicit unavailable snapshot with no answers/result body. HTML source is rendered as text. Submission archive uses the existing reason/password/audit transaction and never rewrites saved answers.
