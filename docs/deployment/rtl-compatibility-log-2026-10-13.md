# Installed RTL compatibility log

User direction: keep existing dependencies, and log missing RTL compatibility. No package or lock change belongs to this slice. This is an installed-source audit of the retained panel, not a claim that every optional toolbox demo has been accepted.

The original LTR Sass remains the authority. `frontend/scripts/direction-mirror.mjs` generates direction-scoped CSS, mirrors physical offsets/shorthands/corners/transforms/keyframes and pairs existing horizontal icon glyphs. Common rules remain shared; logos/flags/images keep their orientation. Native content direction and machine-readable code stay intact.

Missing native **automatic** support is distinguished from having zero RTL capability across an entire package. None of the inspected packages can honestly be labeled wholly incapable of RTL based on this bounded source audit.

The full retained Sass graph currently generates1773 directional rule groups,456 glyph pairs,75 preserved native/content groups and removes6 superseded explicit RTL groups. Five shape declarations are deliberately reported for review: four symmetric accessibility clipping rules (`sr-only`, `sr-only-focusable`, `btn-check`, `visually-hidden`) and the symmetric optional ApexCharts effect mask. They are not physical placement defects and remain unchanged. New asymmetric clip/shape declarations require an explicit mirror handler; they are not silently accepted. Build CSS grows from1,278,205 to1,614,565 uncompressed bytes before minification; actual compressed served sizes are recorded by static acceptance.

Runtime-created inline styles, SVG/canvas coordinates, drag/drop hit areas and third-party portals are component-owned. Current deployment acceptance covers the actual product panel and measured layouts listed in the successor report; optional toolbox surfaces are retained, and their unverified interactions stay logged here for later wiring.
