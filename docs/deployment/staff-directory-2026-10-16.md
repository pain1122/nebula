# Root-only staff directory

October16 user requests `/panel/users` exclude patients/doctors and be reserved for administrators/content managers, preferably root-only. The user explicitly chooses to reserve the directory and define the content-manager role separately. No content-manager role, permissions, seed, migration or live role assignment is added. Root identities remain excluded under the existing protected-identity policy.

Before: admins/root used a general directory with clinical role filters and a generic create form. After: only root admins can open the existing `/panel/users` route or see its Staff sidebar entry. The table loads the separate root-only `GET /api/admin/staff`, pins the admin scope despite pasted patient/doctor URLs, removes clinical filters/columns and limits its create form to admin identities. Current staff means existing admin accounts; mixed admin-plus-patient/doctor accounts are excluded. Search, account state, registration period, sorting/paging and profile links keep the retained Velzon design and ENFA controls.

The server reloads active root authority before and after reading and refuses changed roles. It rejects role overrides and retains bounded filters/private-field redaction/private no-store output through the existing reader. Client cache keys separate staff from clinical queries, and a non-admin staff row fails closed. Existing `/api/admin/users` remains the authorized legacy clinical/general reader; the dedicated patient/doctor pages still use that API with fixed clinical scopes. Staff access is not inferred from those clinical endpoints. Existing admin-identity writes retain their root policy/reason/recent-password/audit safeguards; no live creation or editing is accepted here.

`/panel/users/:userId` remains the existing authorized support profile for clinical directories. Ordinary admins keep metadata-only patient/doctor support access; Back uses the fixed clinical directory, with a safe subject-role fallback for direct links. Its breadcrumb no longer points at the newly restricted staff route. Credentials/private identities/clinical bodies remain hidden. The shared user editor adds an optional staff-only role restriction; default behavior for other callers is preserved.
