# General setting safeguards and runtime defaults

Accepted backend/source slice, October16, Asia/Tehran. The general panel is proposed separately; successful live saves/resets and concurrent MySQL writes remain unaccepted.

| Before | After |
| --- | --- |
| General reader had a reviewed revision, but the older PUT/service did not enforce it. | The existing PUT and direct service require the same actor/scope/state-bound revision, explicit confirmation, strict values and a reason. HTTP retains recent-password confirmation. Active root authority and current roles are reloaded and locked; definitions/values are locked before comparison and persistence. |
| No bounded general reset. | `operation:reset` removes only the selected stored override and takes no value. Missing overrides and same-value saves fail422 without an audit. Audit failure or authority loss rolls back the value/definition/delete and audit together. |
| Stored defaults did not affect consumers. | New booking holds resolve site, then platform, then the existing operator hold configuration. Missing schedule timezone/currency resolve site/platform/registry default. Explicit hospital timezone and rule/offering/checkup currency win; invalid explicit data is refused. |

Exactly three public keys are managed: `booking.pending_hold_minutes` (strict integer5–180), `booking.default_timezone` (valid IANA identifier) and `payments.default_currency` (strict three uppercase letters). Only configured server-owned platform/site scope keys are allowed. User/tenant scopes, unknown/query fields, arbitrary scope keys, missing revisions/confirmation and malformed reset bodies are refused. Existing user preference rows remain untouched; the old general writer can no longer bypass these controls. Existing upload-setting behavior is retained and tested independently.

GET `/api/admin/settings/general?scope_type=platform|site` remains read-only/no-store and now reports backend `write_controls_ready:true` and `runtime_binding_ready:true`. These flags describe the prepared boundary/consumers, not a deployed general-settings page or successful live mutation. The revision includes settings/configuration, actor roles/scope and the marketplace-setting audit sequence, so restoring a previous value cannot revive an old revision. An intervening upload-setting audit can also invalidate a general revision; refresh and review instead of automatically retrying. State comparisons still occur twice on reads. Corrupt/private known-setting metadata and values fail503 without exposing their contents.

PUT `/api/admin/settings/{settingKey}` requires `scope_type`, server-issued `scope_key`, `expected_revision`, `reason` and `confirmed`; optional `operation` defaults to `set`. Set requires a strictly typed `value`; reset prohibits the field entirely. Fresh unknown revisions fail409. Set can provision only its requested registered definition, inside the audited transaction; reads and absent resets never provision. Audit action remains `settings.marketplace.updated`; bounded before/after snapshots now also record `stored`, distinguishing override removal from a saved value. No provider, credential or clinical fields are included.

Runtime compatibility is deliberately narrow:

- Existing holds, idempotent booking replays, paid/completed reservations and payment snapshots never change. The operator hold fallback retains its previous minimum-one-minute behavior when no override exists; the registry default60 is separately disclosed and is not substituted for a custom operator fallback.
- Existing hospital timezones, appointment instants and explicit priced-source currencies stay authoritative. Default currency is a fallback for missing source currency on **new schedule occurrences**; it does not change the catalog create-form prefill, convert prices or relabel stored money.
- Existing occurrences retain individual price/active overrides through `firstOrCreate`. No new booking or materialization was performed live. Runtime lookup reads only its required key, so an unrelated corrupt default cannot block an explicit currency/timezone or hold resolution.
