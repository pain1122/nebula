# Clinical account and hospital/clinic onboarding

Requested October18: replace the Workplace label with Hospitals/Clinics, add real manual doctor/patient/location creation, let doctors select several practice locations and manage different weekly shifts at each, and make the doctor responsible for demo pricing.

## Proposed pages and permissions

Retain existing `/panel/doctors` and `/panel/patients` directories and add their Create buttons linking to `/panel/doctors/new` and `/panel/patients/new`. Add `/panel/hospitals`, `/panel/hospitals/new` and `/panel/hospitals/:hospitalId` (public ULID) for the physical hospital/clinic directory and card/grid detail/edit. Admin/root can manage these clinical directories; the existing root-only `/panel/users` Staff boundary is unchanged. Existing `/panel/schedules` and `/panel/schedules/workplaces/:workplaceId` remain schedule administration. `/panel/schedules/workplaces` is not a registered location-directory URL; link it to the actual schedule list as a compatibility redirect rather than treating the literal word as a workplace ID.

Use the existing Velzon cards/forms/table/detail layout and grouped navigation, translated English/Farsi. No new dependency, schema or design system. The hospital/clinic forms contain name, unique slug, timezone, country/province/city/address and organizational contact/website/profile text. They contain no price or raw HTML/JSON editor. Safe detail/edit has current revision, reason, explicit confirmation, recent password, fresh role checks and atomic audit. No deletion or affiliation approval workflow in this slice.

Doctor/client creation uses role-fixed full pages, with the existing strong initial-password policy and required identity fields. Credentials/private identity values are input-only, never returned or available for subsequent admin read/edit. Use strict allowlists, current active admin/root authorization under transaction locks, reason/confirmation/password step-up and audit rollback. Creation must not silently retry after an uncertain delivery. New doctors also get a real doctor profile, active specialty selection, experience and doctor base fee. Verification starts pending by default; provide a separate explicit **Verify this doctor on creation** choice for the creating admin/root, recorded in the same guarded audit. Doctor self-service cannot grant verification. No existing account is reset, reclassified or assigned a new credential.

## Doctor location selection and schedules

On existing `/panel/profile`, provide an Add hospital/clinic control with bounded search over active organizational records. The doctor selects a location and the active catalog services they personally offer, with a doctor-owned price/currency for each. Save creates only the current doctor's location association and doctor/service affiliations; it does not grant authority over the hospital or another clinician. Refuse duplicates, inactive/archived locations/services, forged owner IDs, stale revisions and mixed unsupported fields. Location cards show organizational location details and keep the existing independent per-location working-day/shift/rest editor. Adding a location creates no appointments until the doctor saves its working hours.

Demo pricing has no hospital charge: doctor service price at the chosen location is the default, with the existing doctor shift/slot override controls available. If no explicit doctor/service price exists, newly materialized appointments fall back to the doctor's profile fee rather than a hospital charge or catalog price. Currency remains from the existing valid currency configuration. Existing materialized slot prices, reservations, payments and audit/history are not rewritten. Doctor price edits apply to future schedule publication; ordinary date/slot overrides retain their existing guards.
